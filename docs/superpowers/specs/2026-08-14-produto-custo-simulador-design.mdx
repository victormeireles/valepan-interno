# Simulador de custos do produto

Data: 2026-08-14  
Status: aprovado em brainstorming

## Objetivo

Permitir que admin estime o **custo por unidade (pão)** de um produto ao alterar vínculos de receita, `quantidade_por_produto` e/ou o **custo unitário dos insumos**, comparando **antes vs depois** por tipo e no total — sem gravar nada no banco.

## Contexto

Em `/config/produtos` já existem vínculos produto→receita (`produto_receitas`) por tipo (massa, brilho, confeito, antimofo, embalagem, caixa) e o modal de Receitas para editar de verdade.

O custo unitário **não** é campo fixo: é calculado na hora a partir de vínculos + ingredientes + `insumos.custo_unitario`, a mesma lógica usada em outro sistema (CMV de NF).

Hoje o catálogo passado ao modal de Receitas **não** inclui `custo_unitario` dos ingredientes — o simulador precisa desses dados.

## Escopo

Inclui:

- Ação **Simulador de custos** no menu ⋮ do produto (junto com Assadeiras / Receitas)
- Modal só-leitura quanto a persistência (estado local; Fechar descarta)
- Comparação antes/depois: breakdown por tipo + total + Δ R$ e %
- Seção **Insumos usados**: custo atual visível e editável só no cenário Depois (um campo por insumo; vale para todos os vínculos)
- Domínio puro de cálculo alinhado ao CMV
- Action admin para carregar vínculos + ingredientes com custo
- Deep-link `?produto={id}&config=simulador`
- Acesso: rota `/config` já exige `interno_config` / `administrar`

Fora de escopo:

- Aplicar/salvar alterações da simulação no produto ou no cadastro de insumos
- Mão de obra, energia, overhead
- CMV de nota fiscal / mapeamento Omie (só a fórmula de custo/unidade)
- Exibir custo/unidade na listagem de produtos
- Histórico ou salvamento de cenários

## Decisão de abordagem

**Modal no menu ⋮ de `/config/produtos`** (aprovado).

Alternativas descartadas: painel dentro do modal de Receitas (mistura edição real com simulação); tela admin dedicada (navegação extra sem ganho).

## Cálculo (alinhado ao CMV)

### Dados

1. **Vínculos** — `produto_receitas` + join `receitas` + `produtos`  
   Filtros: `produto_receitas.ativo`, `receitas.ativo`, `produtos.ativo`  
   Campos: `receita_id`, `quantidade_por_produto`, tipo da receita

2. **Ingredientes** — `receita_ingredientes` + join `insumos`  
   Campos: `quantidade_padrao`, `insumos.custo_unitario` (pode ser `null`)

### Fórmula

Para cada vínculo com `quantidade_por_produto > 0`:

```
custo_da_receita = Σ (quantidade_padrao × coalesce(custo_unitario, 0))
// se custo_unitario for null → parcela 0 e marca insumo_sem_custo

custo_por_pão_daquela_receita = custo_da_receita / quantidade_por_produto
```

Total do produto:

```
custoUnitario = soma de (custo_receita / quantidade_por_produto) de cada vínculo
```

Insumo sem custo **entra no total como 0** e gera flag `insumo_sem_custo` (não remove o tipo do total).

Exemplo: massa `(10×5 + 2×1) / 100 = 0,52` + brilho `2 / 100 = 0,02` → **R$ 0,54 / un**.

### Cenários no modal

- **Antes:** vínculos reais do produto + qtds atuais + `insumos.custo_unitario` atuais
- **Depois:** overrides locais de receita, qtd e/ou custo de insumo; o que não foi editado herda o Antes
- Ambos usam a mesma fórmula
- Override de custo: mapa `insumo_id → custo_unitario` aplicado só no Depois, em **todos** os vínculos que usam aquele insumo (se farinha aparece em massa e brilho, um único campo)

No Depois, a fórmula usa `coalesce(override[insumo_id], custo_unitario, 0)`. Se o usuário preenche um custo onde o cadastro era `null`, a flag `insumo_sem_custo` some naquele insumo no Depois.

## UI / fluxo

1. Menu ⋮ → **Simulador de custos**
2. Modal header: “Simulador de custos” + nome do produto
3. Corpo:
   - Linhas por tipo (mesmo conjunto do modal de Receitas): select de receita + input de qtd no cenário Depois
   - Estado inicial = vínculos atuais (Antes)
   - Tipos sem vínculo: select “Selecione…” + qtd vazia; se o usuário escolher receita + qtd, entram só no Depois
   - Seção **Insumos usados**: união dos ingredientes das receitas do Antes **e** do Depois (se trocar a receita, os insumos novos aparecem). Cada linha: nome, unidade, custo atual (somente leitura), input de custo simulado. Um insumo = uma linha, mesmo se entrar em várias receitas.
4. Painel de resultado (sempre visível / sticky no rodapé do body):
   - Por tipo: custo/un Antes → Depois (Geist Mono, pt-BR)
   - Total Antes / Depois
   - Δ absoluto (R$) e Δ %
   - Avisos: `insumo_sem_custo`, qtd ≤ 0, receita sem ingredientes
5. Footer: apenas **Fechar** (sem “Salvar” / “Aplicar”)

Visual: shell dos outros modais de ProdutosConfig (stone/amber, pt-BR, Material Icons). Copy operacional (“Antes”, “Depois”, “Custo/un”, “Diferença”).

## Arquitetura

| Peça | Responsabilidade |
|------|------------------|
| `ProdutoConfigOverflowMenu` | Nova ação `simulador` |
| `ProdutosConfigClient` | Estado do modal + `syncUrl(..., 'simulador')` |
| `ProdutoCustoSimuladorModal` | UI do simulador (overrides locais) |
| Subcomponentes pequenos | Linha de tipo; lista de insumos; painel de resultado (SRP / &lt;500 linhas) |
| `produto-custo-unitario-calculo.ts` | Domínio puro: custo por vínculo + total + flags; aceita mapa opcional de override de custo |
| Action `getProdutoCustoSimulacao` (ou equivalente) | `requireInternoModulo('interno_config', 'administrar')`; retorna produto, vínculos e catálogo de receitas com ingredientes + `custo_unitario` |

Sem mutation de `produto_receitas` nem de `insumos.custo_unitario`. Sem nova tabela.

## Tratamento de erros / edge cases

| Situação | Comportamento |
|----------|----------------|
| Produto sem vínculos | Antes = R$ 0; Depois só com o que o usuário montar |
| `quantidade_por_produto` ≤ 0 | Tipo não entra no total; aviso |
| `custo_unitario` null | Parcela 0 + flag `insumo_sem_custo` (some no Depois se houver override numérico) |
| Override de custo vazio / inválido | Usa o custo cadastrado (Antes) |
| Mesmo insumo em várias receitas | Um campo; o override vale para todos os vínculos no Depois |
| Receita sem ingredientes | Custo 0 + aviso |
| Receita inativa no catálogo | Não listar no select do Depois (só ativas) |
| Fechar / Esc / overlay | Descarta overrides |

## Testes

- Domínio: casos do exemplo 0,52 + 0,02 = 0,54; null → 0 + flag; várias receitas; qtd ≤ 0 ignorada; override de qtd/receita/custo de insumo muda só o Depois; override de um insumo compartilhado afeta todos os vínculos
- UI: smoke opcional — abrir menu, abrir modal, alterar qtd, ver Δ (se houver padrão de teste client no repo)

## Critérios de sucesso

- Admin abre simulador a partir do produto e vê Antes = custo atual coerente com a fórmula do CMV
- Alterar qtd (ex. massa 953→715), receita/qtd de embalagem/caixa **ou custo de um insumo** atualiza Depois e o breakdown em tempo real
- Fechar não altera vínculos nem `insumos.custo_unitario` no banco
- Avisos de insumo sem custo visíveis sem bloquear o total
